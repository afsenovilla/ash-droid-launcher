# Second-screen design (dual-screen handhelds, "DS beta")

Status: **design approved for the battle menus on 2026-11-25; not implemented yet.** The code on this branch still
draws the previous version (the game's own menu images enlarged), which was rejected after testing on an AYN Thor.
No build is to be started until the owner authorises it.

The mock-ups are generated by `ds_mock.py <pixelfonts.txt> <game folder>/Fonts/power green.ttf <out.png>` (command menu
on the left, move menu on the right). The move menu uses the game's type icons, so the images are not kept here.

## Battle menus: rules the implementation must follow

- Buttons are **drawn by code** at the size of the screen, in Fire Ash's button style: dark outline, white rim two
  pixels thick, bevelled two-tone body, soft shadow straight below. Every layer follows the same corner shape (the
  outer shape shrunk evenly), so the rim never breaks at the corners. Art grid: 206x180 "art pixels", 6 screen pixels
  each on the Thor's 1240x1080 screen.
- Button lettering (FIGHT, BAG, CANCEL...) uses the `cmd` pixel font, white with dark outline, drop shadow and the
  lower part of each letter slightly shaded.
- Texts in the game's font (move names, type, PP, effectiveness) are only drawn at **multiples of 13 px** (the font's
  own pixel grid), otherwise the strokes come out uneven. Base + shadow one font pixel to the right and below.
- **Command menu**: FIGHT large on top (no extra frame around it), BAG and POKéMON below at the sides, RUN smaller
  between them. A row of dots on top shows the state of the player's party (green ok, yellow status, grey fainted)
  and the opponent's on the right.
- **Move menu** (revised and approved): four buttons with a thin frame in the colour of the move's type around a cream panel,
  the same card as the moves screen of the summary. Name on top; below it, the game's own type icon (`types.png`,
  at 3x) with the PP to its right; elements spread out vertically. Effectiveness is a band at the foot of the card
  (green super effective, orange not very effective, grey no effect), only when there is something to say. CANCEL is
  a small centred button at the bottom; Mega Evolution goes to its right when available. The earlier version (thick
  frame, type as a text tag) was replaced.
- **Cursor**: no coloured frame. The selected option bounces a couple of pixels in a loop and its shadow narrows and
  fades as it rises.
- Colours of types and buttons are to be taken from the game's own images at run time, not hard-coded.
- The "game-screen menu: hidden/shown" switch leaves this screen and moves to the launcher's settings.

## Game screen (top)

With the game's menu hidden, the message bar always shows "What will X do?" full width, also while choosing a move,
instead of an empty bar.

## Overworld (design only)

The home screen (generated by `ds_mock_overworld.py`; it shows the game's Pokémon icons, so its image is not kept here) was approved as an MVP on 2026-11-25: top bar with the
current location and the time; the party on the left (icon, name, level, HP bar, status / fainted tag); on the right
POKéMON, BAG, MAP, the profile button (labelled with the player's name, opens the Trainer Card) and SAVE.
SAVE writes the game (with confirmation, only while the game allows saving). Map, bag, Pokémon and profile are
read-only views in this first version; each gets its own mock-up before being built. The Pokémon icons in the mock-up
are placeholders: on the device they are the game's own.

`screen-map.png` (`ds_mock_flow.py`) shows how the screens connect and which ones still have no mock-up.
`overworld-map.png` and `overworld-route.png` are proposals under review (not approved yet): the region map with the
player's marker, and a route sheet opened from the map's place panel that lists the wild Pokémon per method (grass,
water, fishing...) with levels, encounter rate and time of day; species not seen yet show as a silhouette and "???".
Small buttons (tabs) use a one-pixel white rim so the lettering never touches the edge.

### Bag (approved 2026-11-25)

Mirroring the game's own bag screen onto the second screen was tried (build 179) and dropped: not viable. The bag is
instead **replicated natively** from the game's own images, font, colours and layout rules (`UI_Bag` in the game's
scripts), read from the player's copy of the game at run time. `ds_mock_bag.py <game folder> <out.png>` renders the
approved mock-up; its output is not committed because it is made of game art, and nothing of the game ships in the
repository or the APK.

- **Full screen, no bars.** The game's 512x384 bag background is cut along lines where it is uniform and those
  lines are repeated (never scaled): +64 px in the left panel, +44 in the item list, +124 of height in the upper
  part, +32 at the top of the description box. Logical canvas 620x540, shown at 2x (1240x1080).
- **Item list**: 11 rows visible instead of 7, the game's red cursor (extended the same way), quantities on the
  right, CLOSE BAG as the last entry (returns to the home screen).
- **Description box**: taller, its text starts 8 px below the box's top edge instead of on it. The item icon box
  grows from 64 to 88 px (same frame, extended) and is centred vertically; the icon is drawn at 3 screen pixels per
  pixel instead of 2.
- **Pocket buttons**: the strip of 20 px icons becomes two rows of four round touch buttons, drawn by code. The
  whole face of each button takes that pocket's two colours and middle band from the game's `icon_pocket.png`
  (colour row); on top goes only the drawing of that icon (its square background removed), at 3 screen pixels per
  pixel. States: idle (grey ring), selected (wider white ring), pressed (sunk two pixels, darkened to 72 %, no
  shadow); on release the pressed pocket becomes the selected one.
- **Optional larger pocket icons**: if the game folder has `Graphics/Pictures/Bag/icon_pocket_ds.png` (384x144:
  8 columns of 48x48 in pocket order, rows idle / selected / pressed, transparent background, drawn at the game's
  pixel size), the buttons use it instead. The launcher never ships such a file. Pocket 6 is Badges in Fire Ash.
- Read-only in this first version: browsing by touch or with the buttons; using items stays in the game's menu.
- Mock-ups must be judged at the screen's real resolution (1240x1080): halved previews show the 3x elements with
  uneven pixels.


## Region map (approved for now)

Mock-up: `ds_mock_map.py <game folder> <pixelfonts.txt> <out.png> [zoom]`.

- Top bar: region and place on the left, "Estás aquí" on the right.
- The map fills the area between the top bar and the buttons. Integer zoom only: 2x shows the whole region
  and is the default; 3x and 4x are centred on the player and clamped to the map edges. `+` / `-` buttons sit
  over the bottom right corner of the map; drag or D-pad to pan when zoomed in.
- Buttons: POKéMON SALVAJES (opens the route sheet) and VOLVER.
- The game's map image mixes pixel sizes (terrain at double pixels, buildings at single pixels) and carries the
  region logo; both come from the player's file and are shown as they are.

## Wild Pokémon sheet (approved)

Mock-up: `ds_mock_route.py <game folder> <pixelfonts.txt> <out.png>`, with the real table of Route 1.

- Fire Ash's `encounters.dat` only has Land, Cave, OldRod, GoodRod, SuperRod (and BugContest): no surfing and
  no time-of-day tables. Tabs are therefore HIERBA or CUEVA, and PESCA (split by rod); only the ones the map
  has are shown. No day/night tags.
- Entries of the same species are merged: rates added, level range widened. Sorted by rate.
- Each row: the game's icon at 2x, name, levels, rate bar and percentage. Five rows visible, the list scrolls.
- Species not seen in the Pokédex: flat silhouette of the icon and "???" as the name; levels and rate stay visible (decided).
- Rows are capsules with the same corner radius as the buttons; tab labels keep clear of the rim.

## Party (approved)

Mock-up: `ds_mock_party.py <game folder> <pixelfonts.txt> <out.png>`.

- Built from the game's party images (round panel for the first slot, rect for the rest, faint and selected
  variants, ball, HP bar, level and status images), the Pokémon icons and fonts, with `UI_Party`'s colours.
- Panels: widened to 296 px and made 138 px tall by repeating lines of the image, shown at 2x, two columns
  with the right one 16 px lower as in the game.
- Contents: everything inside a panel is shown at 3x and re-laid out (name on top, HP bar under it, level,
  status and HP numbers on the bottom row; HP written without spaces). Chosen over a variant with only icon
  and name at 3x. A straight 3x copy of the game's layout needs 768 px per panel.
- Bottom band: help line and VOLVER.

## Party: reordering and actions (approved)

Mock-ups: `ds_mock_party.py <game folder> <pixelfonts.txt> <out.png> drag` and `... actions`.

- Reordering is done on the party screen by dragging a panel onto another one; there is no "Switch" button.
  While dragging, the held panel follows the finger with a shadow under it and uses the game's own
  "switching" panel images, as does the panel under it; its own slot shows the blank panel. Letting go swaps
  the two (swap, as in the game, not insert: decided); letting go anywhere else puts it back. With the buttons: hold the confirm button on a Pokémon to
  pick it up, move with the D-pad, confirm to drop.
- A short touch (no drag) opens that Pokémon's actions: its panel alone at the top, widened to 356 px so the
  HP bar clears the icon, and under it the options the game gives for it except Switch (Summary, its field
  moves, Item or Mail) stacked as medium buttons as wide as the panel, in the approved style, one colour per
  kind. Buttons are 162 px tall; three fit at this size, with more the rows get lower.
- The game's "Cancel" is the VOLVER button at the bottom right, as on the other screens.

## Summary remote (approved)

Mock-up: `ds_mock_party.py <game folder> <pixelfonts.txt> <out.png> summary`.

- DATOS opens the game's own summary screen on the top screen, untouched. The second screen is its remote:
  previous / next Pokémon (arrows beside its icon and name), one button per page of the summary (the current
  one in colour, the rest grey) and VOLVER.
- Page labels will follow the game's own page titles. Not designed yet: move details on the moves page.
- OBJETO: a second level with the same stacked buttons (USAR, DAR, and QUITAR when holding something); USAR and
  DAR open the bag to pick the item. Field moves: the menu closes, the second screen goes back to home and the
  move runs on the top screen with the game's own messages.

## Home button (decided)

Every screen more than one step away from the overworld home shows a round home button (green, house glyph
drawn by code) to the left of VOLVER. VOLVER goes up one level; home goes straight back to the overworld home.
First-level screens (bag, party, map, profile) only show VOLVER, which already leads home.

## Profile (approved)

Mock-up: `ds_mock_profile.py <game folder> <pixelfonts.txt> <out.png>`.

- Replica of the game's trainer card (the one the pause menu opens): card image, player sprite, the five rows
  and the ID with `UI_TrainerCard`'s positions and colours, and the badges of the current region. Shown whole
  at 2x, centred, over the card's own background colour. VOLVER under it.
- Arrows in the side margins move between this card and the four pages of the game's GC card (same method:
  the page image whole, labels and awards at `UI_GCCard`'s positions), wrapping around as the game does. In
  the game that card is opened with the GCCARD item, so those pages are only offered when the player has it;
  without it there are no arrows. Bottom left: which card is shown (`ds_mock_profile.py ... <out.png> 1-5`).

## Save (approved)

Mock-up: `ds_mock_save.py <game folder> <pixelfonts.txt> <out.png> [done]`.

- The game's save screen is only a text window, so this screen is built from the game's load screen: its
  background (`loadbg`) and its selected "Continue" panel (`loadPanels`) with the player's walking sprite, the
  party's icons and `UI_Load`'s texts and colours. What is shown before saving is the card found when loading.
- Background and card are shown at 3x, so the card spans the screen. The card is made 64 px taller by
  repeating one of its lines; it carries more than the game's: ID under the name, badges, Pokédex as
  owned/seen, time, money and start date, and a looser party grid.
- The question is the card's title ("¿Guardar la partida?", then "Partida guardada"). A bar drawn by code
  under it holds GUARDAR (large, green) and VOLVER; after saving only VOLVER stays. The game's warning about
  overwriting a different save file is shown as a second confirmation before saving.
- The home screen's GUARDAR button is greyed out while the game has saving disabled.

## Text weight (rule)

Small text is never drawn bare on a coloured background: on the Thor it reads too thin. Text in the game's font
goes at 52 px or more, dark with its grey shadow on a cream or light panel (or white with a dark shadow on dark),
labels at the same size as their values.

## Touch feedback and scrolling (rules)

- Every button has a pressed state while the finger is on it, the one approved for the bag's pocket buttons: it
  sinks two pixels, gets darker and loses its shadow; it acts on release, and sliding the finger off cancels.
  This is separate from the bounce of the option selected with the D-pad.
- Lists (bag items, wild Pokémon) scroll by dragging the list itself, and the bar on their right can be
  dragged to move fast; its arrows step one row and repeat while held.

## Physical controls (rules)

Every second-screen screen works with touch and with the buttons; nothing is touch-only.

- Battle: as today. The D-pad, confirm and cancel drive the game's own menu and the second screen follows it
  (the option under the cursor bounces); touching does the same thing through the game.
- Overworld, home screen: the buttons belong to the game (walking, talking). The home screen is touch, plus the
  entry point below.
- Overworld, any other second-screen screen (bag, party, map, profile, save and what hangs from them): while it
  is open the buttons belong to it and the game does not receive them. D-pad moves the cursor, confirm presses
  the option under it, cancel is VOLVER / CANCELAR, the shoulder buttons change pocket, page or card where
  there is one, and holding confirm picks up a Pokémon or a move to reorder it.
- Entry point with the buttons (decided): on the overworld the game's menu button no longer opens the game's
  pause menu on the top screen; it puts the cursor on the second screen's home buttons. Cancel from there gives
  the buttons back to the game.

## Bag out of battle, new layout (approved; replaces the two-column bag)

`ds_mock_bag_battle.py <game folder> <out.png> <pixelfonts.txt> world|item`. Proposed to replace the two-column
bag (`ds_mock_bag.py`): the layout approved for the battle bag (pockets in a row on top, list as wide as the
screen with each item's icon, seven taller rows), with the description and VOLVER at the foot. Touching an item
opens that item's options at the foot in a 2x2 grid of equal buttons (USAR, DAR, TIRAR, or REGISTRAR / LEER
when they apply, and CANCELAR, which brings the description back); the foot grows over the last row of the
list to hold them. One row of four was dropped: it does not fit in German or French. The bag picture, the pocket name, the big item box and
the CERRAR MOCHILA entry go away.

## Languages (rule)

The game ships in English, French, Spanish and German (`Settings::LANGUAGES`). Button labels are the game's own
translated strings, never hard-coded Spanish, and every button is sized for the longest of the four words
(for instance REGISTRIEREN / ENREGISTRER, WEGWERFEN, ABBRECHEN, SAUVEGARDER). Where a row of buttons cannot
hold the longest words, the layout changes for every language (as in the bag's item options), not per language.
To check when implementing: the home screen's save button and the map's wild Pokémon button.

## Audit of the approved screens against the rules (2026-11-25)

Fixed in the mock-ups:
- Battle bag: USAR was too narrow for BENUTZEN / UTILISER and left the description three short lines; foot redone.
- Home: buttons widened (SAUVEGARDER, SPEICHERN); party levels at the same size as the names.
- Route sheet: levels and the "???" note were small unshadowed text; now 52 px with shadow.
- Party options, held item options, summary remote, battle party, save: the selected button was drawn lifted,
  which made the gaps uneven; static mock-ups now draw every button at rest.

Left for implementation:

- Save card: "label: value" rows share 204 px; German "Gestartet:" with a full date and French time labels may not

## Home screen party list (revised)

The party on the home screen is no longer drawn by code. It is six of the game's own party panels (`panel_rect`,
`panel_rect_faint`, `panel_blank`) with the game's ball, HP bar (`overlay_hp_back`, `overlay_hp`), level image and
status icons (`statuses.png`), plus each Pokémon's icon, name and HP, all at 2x. The panels are made 340 px wide by
repeating a column and 80 px tall by leaving out lines of their two flat bands, so six fit in a column beside the
five buttons. Rule that follows: where the game has an image for something (status, HP bar, panels, type and
category icons), that image is used; code-drawn elements are for what the game has no art for.
